# 多人房间与 Render 中转部署

本项目已提供独立中转程序和大厅联机界面。房主电脑运行规则、AI 和存档；Render 管理房间、确认连接身份并协助浏览器建立 WebRTC 直连。直连成功后，玩家操作和个人视图经浏览器间的加密数据通道传送；直连失败或断开时自动改走现有 Render 中转。每位玩家运行同一版本的桌游大厅，无需另装穿透工具，也无需配置路由器。

## 在 Render 部署

两种方式任选其一。

### 使用独立中转仓库（推荐）

1. 解压 `artifacts/boardgame-relay-render-save-resume.zip`，将解压得到的文件上传到自己的 GitHub 仓库。`package.json`、`server.js`、`render.yaml` 应直接位于仓库根目录。
2. 登录 <https://dashboard.render.com/>，选择 **New → Blueprint**，连接这个仓库。配置文件会创建一个 Node Web Service，并自动生成 `RELAY_SECRET`。
3. 首次可用 Free 实例测试。部署成功后复制服务的 HTTPS 地址，例如 `https://你的名称.onrender.com`。
4. 在浏览器访问这个地址的 `/health`。看到 `{"ok":true,"service":"boardgame-relay","protocol":1}` 表示 HTTP 服务启动成功；实际 WebSocket 连通性还需要在大厅创建和加入房间验证。

也可使用 **New → Web Service** 手动部署，填写：

| 字段 | 值 |
|---|---|
| Language | Node |
| Root Directory | 留空 |
| Build Command | `npm ci` |
| Start Command | `npm start` |
| Health Check Path | `/health` |
| 环境变量 `RELAY_SECRET` | 自己生成的至少 32 字节随机密钥，长期保持不变 |

`RELAY_SECRET` 只保存在 Render 中，不需要发给玩家或填写进大厅。可在本机用 `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` 生成。更换此密钥会让已有重连凭证失效。

### 使用完整项目仓库

如果将整个项目放进 GitHub，使用项目根目录的 `render.yaml` 创建 Blueprint；它已指定 `rootDir: relay`。手动创建 Web Service 时则将 **Root Directory 填为 `relay`**，其余配置与上表相同。

部署只需要 `relay/`，不需要上传图片、音乐、个人模型配置或存档。中转不需要配置 AI 密钥，也不需要数据库。本地默认依然只监听回环地址，不需要改为 `0.0.0.0`；只有 Render 上的中转服务监听公网入口。

## 大厅里怎么玩

房主：

1. 启动更新后的大厅，选择五子棋、井字棋或诡镇奇谈。
2. 在开局设置中选择 **联机房间**，用唯一的 **席位数量** 设置总人数。
3. 逐席选择 **等待玩家加入**、**随机 AI** 或具体 AI 角色。AI 席位立即预留，玩家不能加入；所有玩家席位入座并准备后才能开始。
4. 点击开局按钮创建等待房间，再点开右上角悬浮房间栏（默认收起）里的 **复制邀请**，将完整内容发给朋友。
5. 等朋友点击准备后，点击 **开始联机对局**。

加入者：

1. 启动相同版本的大厅，点击 **加入联机房间**。
2. 粘贴完整邀请（以 `BGH1` 开头），自动使用邀请中的地址和房间码；也可仅输入房间码，使用联机设置中的服务。
3. 可自动分配空闲玩家席位，也可选择指定席位；继续存档时选择自己原来的席位。加入后点击 **准备**。AI 席位不可加入；游戏开始后不接受新成员。

双方不需要注册 Render。大厅已内置默认中转地址 `https://boardgame-relay.onrender.com`，无需手动输入。地址统一在 **设置 → 联机** 修改并保存；创建和加入界面不再重复显示地址输入框。也可以在分发环境中设置 `BOARDGAME_RELAY_URL` 覆盖内置默认值。完整邀请中的地址优先于设置中的地址。邀请不是普通网页链接，应粘贴进大厅。

预留 AI 席位需要更新中转程序；新版 `/health` 的 `features` 包含 `reserved-ai-seats`。旧中转若无法确认 AI 席位预留，大厅会提示更新并撤销创建，避免其他玩家误占 AI 席位。中转重启后会同时恢复 AI 席位。

联机只比较两个版本号：大厅版本号（`package.json` 的 `version`）与游戏版本号（`boardgame-mod.json` 的 `version`）。两者一致即可加入，中转不再校验游戏文件的逐字节指纹，因此改注释、样式或本机资源不会把玩家挡在房间外；只有真正需要同步升级时才提示双方更新。内置且没有 `boardgame-mod.json` 的游戏按 `0.0.0` 比较，实际由大厅版本号决定兼容性。图片和音乐不参与版本比较，也不会经中转传输。五子棋、井字棋的“AI 先手”设置在双人联机时对应第二席位执黑先行。

## 断线、存档与权限

诡镇的 **存档管理** 分为 **单人存档** 和 **联机存档**。房主在联机存档中点击 **创建房间继续**，会用原有席位布局创建一个新的等待房间。复制新邀请给朋友，让每个人选择原来的席位加入并准备，再由房主点击 **继续存档对局**。原手牌、调查员、牌组、战役进度、待决选择及 AI 席位均保留；等待期间不会推进游戏。房主仍固定为席位 1，指定席位需要新版中转（`features` 包含 `select-seat`）。单人读取接口会拒绝联机存档，避免多人对局误以单人方式运行。

诡镇按存档内部的结构、规则和游戏数据版本检查兼容性；仅更新界面或展示资源不会使旧存档失效。真正不兼容的存档会保留并显示原因。

房主自己的行动在本机执行；其他玩家的操作仍由房主校验。双方浏览器保持打开时会优先尝试 WebRTC 直连，房间栏显示“直连”或“中转”。Render 仍负责房间、信令和连接恢复；关闭房主浏览器但保留大厅程序运行时，数据会回到 Render 中转。某些运营商或防火墙无法直连，无需手动切换。首次连接与重连同步完整的个人视图，后续只发送变化部分，且继续按玩家隐藏手牌和私聊。界面在状态变化时立即更新，无需等待固定轮询间隔。网络往返和 AI 模型耗时仍会影响实际响应，双方需更新到同一版本。

- 浏览器刷新会恢复当前房间。每个本机大厅服务同一时间连接一个房间；同一大厅端口打开多个标签页代表同一玩家。
- 房间信息是右上角的悬浮房间栏，默认收起成小胶囊，不占牌桌空间；点开后才显示 **复制邀请 / 强制同步 / 联机设置 / 解散房间** 等操作，展开状态会记住。收起时仍显示房间码、直连/中转/席位和错误提示。
- 房间栏的 **强制同步** 是手动恢复入口：任何操作看起来卡住（按钮没反应、界面停在旧提示、状态与房主不一致）时都可点击。它会解除本客户端的临时忙碌/错误状态，请房主重发一份完整快照，并强制拉取全量对局状态；只重建界面，不提交游戏动作、不改变对局内容。若同步后提示「房主/AI 仍在结算」，等结算结束即可；若提示失败，先确认联机连接，仍不行再刷新页面。诡镇奇谈的 Mod 也会在强制同步时清掉自己卡住的演出/选择/行动门闩。
- 网络断线自动重连并恢复原席位。Render 重启后，房主会使用签名凭证恢复原房间码，其他成员随后恢复连接。必须使用同一个 `RELAY_SECRET`，并保持单实例部署。
- 默认启用持久化时，本机将重连凭证保存到大厅数据目录的 `online-connection.json`，游戏快照仍存放在 `sessions/`。房主和加入者重新启动程序会自动尝试回到房间；房主离线期间对局暂停。关闭 `BOARDGAME_PERSIST` 则不支持程序重启恢复。
- 重连凭证有效期为签发后 7 天，成功重连会换发新凭证。游戏升级导致版本变化时，应重新建房。不要分享重连凭证文件。
- 主动解散房间会使所有成员退出并清除自动恢复信息。游戏中的加入者主动离开后，在同一大厅程序内再次使用原邀请可以回到保留席位；若随后关闭了该大厅程序，则不再自动恢复此主动退出的连接。
- 当前版本没有房主迁移、观战或开局后替补。等待阶段断线的成员仍保留席位；无法返回时可解散并重新创建房间。
- 重开、继续 AI 和手动保存由房主管理；玩家只能操作绑定的席位。操作包含对局版本与唯一编号，重复请求不会重复落子。
- 诡镇奇谈每位真人自行选择调查员和构筑卡组，只有自己的手牌可见。私聊只发送给参与者。联机聊天支持真人互聊及向指定 AI 私聊；单人模式的战术备忘功能保持原样，联机中暂不提供备忘编辑。
- 诡镇联机只传送近期演出的完整画面快照，避免长战役历史撑大每次同步；文字事件记录保持完整。整桌演出快照只保留最近 24 条，更早的在提交时就被剥掉（同步与本地存档同样处理），这样长战役的事件日志和存档不会随步数膨胀。断线或房主离线时，行动、准备和牌组提交暂停，恢复后继续原待决选择。
- 中转不暴露房主 HTTP 接口，加入者不能修改房主的模型设置。公网中转传输使用 WSS，WebRTC 直连使用浏览器的 DTLS 加密。Render 仍参与信令与身份管理，本实现不提供独立于 Render 的端到端身份认证。

## 本机验证

开发环境使用 Node.js 22.15+（当前已在 Node.js 24 测试）。大厅使用 Node 内置 WebSocket，不增加 Windows 发布包的运行时依赖；中转依赖 `ws`。

```powershell
npm install
npm run relay:install
npm run relay:start
```

中转默认监听 `10000`，在大厅输入 `http://127.0.0.1:10000`。需要两名玩家时，启动两个使用不同 `BOARDGAME_PORT` 和 `DSH_HOME` 的大厅进程；仅打开同一大厅的两个标签页不能模拟两位玩家。公网地址只允许 HTTPS/WSS，明文 HTTP/WS 仅允许本机调试地址。

```powershell
npm run test:online
npm run test:hall
npm run test:hall:browser
```

测试覆盖两台大厅建房与加入、准备、轮流行动、越权和过期版本拒绝、重复提交、私聊隔离、中转重启、本地房主重启。浏览器测试验证直连操作与状态同步、断开后的中转接管，以及诡镇各席位手牌隔离。诡镇另有四真人第一关至结算和关间继续、私人检定与求助、敌人目标和攻击顺序、待决中重连、房主重启后的手牌与选择恢复，以及第二席位准备和换牌的浏览器回归。同步测试检查延迟响应不会倒退状态、忙碌期间收到的更新最终会重绘，以及历史演出快照的传输大小受限。

## Render 使用边界

免费服务无入站流量 15 分钟会休眠，唤醒约需一分钟，且有用量限制。大厅会发送连接心跳并在中断后重连；即使全部玩家直连，Render 仍承载信令和心跳。正式长期使用应按实际需求选择服务实例。第一版采用单进程内存房间表，**不要启用多实例扩容**。中转重启的恢复依靠房主仍在运行或重新启动，以及持久不变的签名密钥。

官方资料：<https://render.com/docs/web-services>、<https://render.com/docs/websocket>、<https://render.com/docs/free>。

本地测试成功不代表已经部署到 Render，也不代表所有运营商网络都可访问。部署后应在房主和朋友的实际网络上完成一次建房、加入和落子检查。
